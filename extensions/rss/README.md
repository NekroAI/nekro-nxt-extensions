# RSS 订阅

让智能体按频道订阅 RSS 2.0、RSS 1.0 或 Atom。首次订阅只记住已有文章；周期检查没有更新时不会唤醒智能体，有更新时交给智能体决定如何转述。

## 配置

| 配置             | 说明                                                                           |
| ---------------- | ------------------------------------------------------------------------------ |
| 检查间隔（分钟） | 15、30、60 或 180，默认 30。新订阅使用当前配置；修改后需取消并重新订阅已有源。 |

周期任务使用 UTC 的五段 cron：15/30 分钟在每小时相应刻度检查，60 分钟在整点检查，180 分钟在每三个小时的整点检查，并非从订阅时刻开始计时。不需要凭据，不支持带账号密码的订阅地址。

## 工具

| 工具               | 说明                                                                                              |
| ------------------ | ------------------------------------------------------------------------------------------------- |
| `subscribe_feed`   | `url` 是完整的 HTTP(S) 订阅地址，`label` 可选（最多 80 字）；每频道最多 20 个，同地址不会重复订阅 |
| `list_feeds`       | 列出订阅、序号、最近检查时间、连续失败次数与最近一条新内容                                        |
| `unsubscribe_feed` | 提供 `url` 或 `index` 其中一个，同时取消周期任务；序号从 1 开始，以最近一次列表为准               |
| `check_feed_now`   | 立即检查；省略 `url` 时以每批最多 4 个并发检查本频道全部订阅，只能检查已经订阅的源                |

例如对智能体说「订阅 https://news.example.com/feed.xml，名称是示例新闻」，随后说「立即检查示例新闻」或「列出本频道的 RSS 订阅」。

每个源记住最近 200 个条目标识（保存 SHA-256 摘要，不截断标识；状态按订阅地址的摘要存放），新一次检查优先保留当前源中的标识，再补旧标识。超出记忆范围的旧文章重新出现时，可能被视为新内容。每个源一次最多返回 5 条，其他新条目同样标记为已见，不会留到下一次补发；多源手动检查的模型文本最多展示 5 条，结构化结果保留各源的返回条目。没有发布时间或链接时会明确说明。

周期任务连续取回失败达到 3 次时，给智能体一条提醒，请它告知用户检查订阅源；同一轮故障只提醒一次，之后的失败保持静默，直到一次成功检查把失败次数与提醒标记一并重置。手动检查失败时直接返回失败说明，不额外提醒，但同样计入连续失败次数。无更新或取回失败时保留最近一条新内容，首次订阅不把历史内容写成新内容。

周期任务可能被管理员或智能体在任务列表中删除。`list_feeds`、`check_feed_now` 以及对已订阅地址再次调用 `subscribe_feed` 时，会核对每个订阅的任务是否仍然存在，缺失时按原间隔重建；后者会提示「已恢复定时检查」。某个源的去重记录丢失时不会报错，下一次成功检查重新记住当前条目作为基线，这次不推送。

## 权限

- 访问任意公网地址：订阅源由用户在工具调用时指定，不能预先列出域名或用固定配置限定；取回与重定向仍由宿主校验，私网地址由宿主拦截。
- 只使用 `channel` 存储，订阅与去重记录按频道隔离；每个源独立保存状态，避免整个列表接近单值 256 KiB 上限。
- 创建运行时周期任务：SDK 的配额按智能体计算，声明最高支持的 50 个，供多个频道共享；每频道另限 20 个，达到智能体总配额时创建订阅会返回错误。

不读取聊天历史，不使用模型辅助调用，不声明浏览器数据权限，不直接向频道发送消息。

## 作为参考

示范 `defineTool<Args, Result>`、频道作用域存储、`jobs.schedule/list/cancel` 和 factory 阶段的 `onJob`。工具输入不合法、外部服务或存储出错时返回 `{ ok: false, message }`；导入验证样例使用非法空地址或序号，确保没有网络访问、订阅、取消或检查写入。

同一频道的操作在 Activation 内串行执行，避免并发重复订阅与重复消费条目。手动操作未完成时，周期检查静默跳过当次，到下一周期再检查。取回与解析限时 8 秒，晚到响应不会修改存储；SDK 不提供取消底层请求的接口。存储与任务没有事务，订阅列表保存失败会取消刚创建的任务；取消订阅时若存储写入失败，可重试取消以清理列表。
