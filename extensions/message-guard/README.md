# 消息守卫

在消息入库后、唤醒智能体前，按关键词决定隐藏、静默或唤醒。规则只影响启用此扩展的智能体；**消息始终保留在频道记录中**，屏蔽不是撤回或删除。

## 配置

| 配置                         | 说明                                         |
| ---------------------------- | -------------------------------------------- |
| 屏蔽关键词 `blockedKeywords` | 命中任一项后，对智能体隐藏并禁止本条消息唤醒 |
| 静默关键词 `silentKeywords`  | 命中后不唤醒，但智能体之后仍能看到消息       |
| 唤醒关键词 `wakeKeywords`    | 命中后即使没有提及智能体，也强制唤醒         |

三项都是字符串数组，默认 `[]`。例如屏蔽填 `['测试广告']`、静默填 `['测试闲聊']`、唤醒填 `['请回答']`。在配置表单逐项填写，不需要输入 JavaScript 表达式。

匹配使用普通文字包含关系，不是正则表达式，也不做分词。消息与关键词都先做 Unicode NFKC 规范化，再转小写：`Test`、`TEST`、`Ｔｅｓｔ` 会匹配，半角片假名也会规范化为全角。NFKC 还会折叠部分兼容字符。关键词首尾空白会去掉，空项和规范化后的重复项会忽略；消息内部空格不会删除。

同一条消息命中多类规则时，**屏蔽 > 静默 > 唤醒**，即使提及智能体也是如此。屏蔽与静默都不附加标注，静默的消息原样保留，不额外占用上下文。未命中时保持原有触发策略。

## 权限

- 仅声明 `inboundHook`：`reads: 'all'`、`mayHide: true`、`mayForceTrigger: true`、`timeoutMs: 500`。
- 需要读取绑定频道的全部入站消息，才能唤醒原本不会触发的消息。这属于高风险读取能力，启用时需要确认。
- 处理只进行本地文字匹配，不调用网络、存储或模型，不外发消息，不注册工具和界面。规则在配置随 Activation 切换时重新加载。
- 超时或出错时宿主按默认策略处理；宿主会持久保存消息决定，恢复时不重新运行。多个入站扩展同时生效时，宿主以抑制触发优先，任何扩展的隐藏决定都能生效。

## 当前限制

公开 SDK 的入站消息只提供发送者 `memberId` 与可选显示名，**没有机器人身份标记**，因此未提供“忽略机器人消息”配置。不会通过昵称、是否提及智能体或成员 ID 猜测身份。其他机器人的消息仍按关键词规则处理。

## 作为参考

示范在 factory 阶段调用 `harness.onInbound`、Schemastery 的字符串数组（`type: 'array'` 与 `inner: { type: 'string' }`）、固定优先级与 NFKC 匹配。Manifest 允许空贡献，因此无需加入额外的 `guard_rules` 工具。
